# Minecraft 26.4 Snapshot 1

欢迎来到 26.4 的第一个快照！我们以一系列技术更新和改进作为开端，其中包括 Vulkan 成为默认图形 API。

## 更改

### 世界生成

- 从洞穴与山崖之前版本升级的世界，现在也将在旧区块下方生成硫黄洞穴

### 方块、物品和实体的细微调整

- 红色和棕色蘑菇现在可以放置在顶部表面完整的任意方块上，无论光照条件如何
    - 除非亮度小于 13，或其支撑方块覆盖了光照要求，否则它们仍然无法扩散

### “图形 API”视频设置

- “默认”现在的行为与“优先 Vulkan”相同
- 如果检测到启动崩溃，游戏将不再自动更改图形 API 设置。

## 技术性更改

- 数据包版本现为 122.0
- 资源包版本现为 98.0

### 网络协议

#### 添加了 `minecraft:mod_list` 自定义数据包负载

- 此数据包旨在告知服务器客户端模组信息，以简化调试
- 原版客户端在配置阶段开始时发送一个空数据包，因为它不知道任何模组——这仍然是第三方模组平台的责任

#### 修改了 `minecraft:intention` 数据包

- 服务器绑定的 intention 数据包中的 `host` 字段现在可以包含额外参数（之前它只存储用于连接服务器的域名）
    - 新格式类似于 URI 查询字符串——域名后面现在可以选择性地跟一个 `?` 字符，然后跟由 `&` 字符分隔的 `key=value` 对
    - 空值可以省略（包括 `=` 符号）
    - 键和值按照标准 URI 规则进行转义（“百分号编码组件”）
    - 以 `_` 开头的键保留供原版使用
    - 示例：`example.com?key1=value2&key2`
    - 用户现在可以在服务器列表中的任何“服务器地址”字段中输入属性
        - 此外，任何形式为 `<id>@<host>` 的地址都将被解析为 `<host>?_id=<id>`
    - 如果服务器使用 SRV DNS 记录，`host` 字段将同时包含原始域名和解析后的域名
        - 如果解析后的域名与原始域名不同，解析后的域名将用作“主”域名，而原始域名将作为 `_o`（“origin”）属性添加
        - 示例 host 字符串：`<重定向域名>?_o=<原始域名>:<原始端口>`，而 intention 数据包中的 `port` 字段将设置为解析后的端口值
    - 字段大小已扩展到 1024 个字符
    - 注意：由于 `minecraft:intent` 数据包未加密，属性不应用于任何安全敏感目的

#### 修改了 `minecraft:transfer` 数据包

- 添加了 `properties` 字段——一个字符串到字符串的映射，其中的属性将被添加到发送到目标服务器的 `minecraft:intent` 数据包中的 `host` 字段

### 专用服务器属性

- 添加了 `allowed-connection-ids`
    - 一个逗号分隔的 ID 列表
    - 如果非空，服务器将把值与 `minecraft:intent` 数据包中的 `_id` 属性进行匹配
        - 如果没有匹配项，服务器将拒绝连接
    - 这适用于状态连接和登录连接，因此任何在服务器地址中没有正确 `_id` 的用户都将看不到状态信息，也无法加入服务器
- 添加了 `status-contact-details` 字段
    - 如果非空，此字段的值将发送到 `minecraft:status_response` 数据包 JSON 负载中的 `contact` 属性下
    - 此值旨在用于指示联系服务器所有者的方式，即使没有网站或其他相关信息
    - 此字段旨在人类可读，但对字段格式没有其他限制
- 添加了 `enable-legacy-status` 字段
    - 此选项允许禁用现有的旧版（1.7 之前）服务器状态和 ping 协议处理
    - 为保留现有功能，值默认为 `true`
    - 注意：需要设置 `enable-status` 才能设置任何状态信息（现代或旧版）

## 数据包版本 122.0

- 多噪声生物群系源中不同生物群系的条目，现在不能在所有具有相同偏移的噪声参数上重叠

### 命令

- `fillbiome` 命令现在将以方块精度填充生物群系
- 从浮点类型到整数类型的 NBT 转换现在总是在向下取整后转换为最接近的可能有效数字

### 世界生成

#### 地物

##### 更改了 `straight_trunk_placer`

- 添加了 `trunk_width` 字段
    - 可选整数提供器，树干以原点为中心的宽度
    - 默认为 1.0

#### 放置的地物

- 现在会验证生物群系中包含的放置地物在 XZ 平面上的可能范围
    - 地物放置只能发生在 3x3 区块区域内：因此，放置地物选择该范围之外的位置是无效的
    - 注意：当前未考虑地物本身的大小，这可能仍然会溢出区块

#### 放置修饰器

##### 更改了 `cuboid`

- `xz_size` 和 `y_size` 已调整为表示长方体实际大小，而不是隐式地大 1 个方块
    - 因此，`xz_size` 为 `2` 将实际产生 2x2 的长方体，而不是 3x3

##### 更改了 `fixed_placement`

- `positions` 现在至少需要一个元素

#### 噪声设置

- `default_block` 字段已被移除
    - 现在始终为 `air`——任何其他方块都应由材料规则定义

#### 材料条件

##### 更新了 `minecraft:steep`

- 不再以顺序相关的方式考虑侵蚀恶地“表面延伸”的高度修改

### 标签

#### 生物群系标签

- 添加了 `#generated_in_below_zero_retrogen`——在洞穴与山崖之前的世界下方生成的生物群系
- 添加了 `#is_cave` 集合标签

## 资源包版本 98.0

### 着色器与后处理效果

#### 顺序无关透明度着色器

- 通过用基于深度分箱的累积替换基于小波的数学，简化了 OIT 算法
    - 至少在部分设备上略微提升了性能
    - 平均减少了浮点精度问题
    - 移除了 `OIT_WAVELET_RANK` 着色器定义
    - `OIT_COEFF_COUNT` 着色器定义被 `OIT_NUMBER_OF_DEPTH_BINS` 取代
    - `OIT_COEFF_ATTACHMENT_COUNT` 着色器定义被重命名为 `OIT_TRANSMITTANCE_TARGET_COUNT`
