# Minecraft 26.4 快照 8

### Minecraft Java 版快照

看来我们的末影龙把飞行技巧忘了一些！在 26.4 快照 8 中，我们修复了末影龙飞行行为的多个问题，帮助它重回正轨。我们还加入了两种新语言的支持，以及一些小幅调整。

祝屠龙愉快！

## 新特性

- 为游戏加入了爪哇语和查瓦卡诺语（Zamboanga）的支持

## 更改

- 修复了末影龙战斗中导致末影龙无法正常移动的一些问题

### 方块、物品和实体的小幅调整

- 在创造模式物品栏中，将雪和雪块放在了雪砖系列旁边
- 现在所有亡灵生物都免疫冰冻状态效果
- 降低了冰球造成的伤害
- 低温硫方怪原型不再漂浮，以与具有相似属性的其他原型保持一致

## 技术性更改

- 数据包版本现在为 127.0
- 资源包版本现在为 103.0
- `terrain.vsh` 中的地形顶点数据现在从纹素缓冲区获取，而非传统的顶点缓冲区
- 更改了地形区段网格数据中顶点数据的打包方式

### 网络协议

- 实体位置同步数据包现在包含完整精度的头部旋转数据

## 数据包版本 127.0

### 校验

- 以下注册表中的大多数校验问题不再阻止元素加载：
  - `minecraft:loot_table`
  - `minecraft:predicate`
  - `minecraft:item_modifier`
  - `minecraft:slot_source`
  - `minecraft:context_float_provider`
  - `minecraft:context_int_provider`
  - `minecraft:villager_trade`
  - `minecraft:advancement` 中的触发器字段
  - `minecraft:enchantment_effect_component_type` 实例中的 `requirements` 字段
- 以下问题现在会被视为错误，可能阻止数据包加载或导致命令编译失败：
  - 待校验的元素通过标签或命名空间 ID 递归调用自身
  - 运行时提供的上下文中缺少待校验元素所需的任何上下文值
    - 例如，修饰器类型 `minecraft:apply_bonus` 使用 `tool` 上下文值，因此不能用于提供 `minecraft:command_modifier` 上下文的 `item ... modify` 命令，因为该上下文没有 `tool` 值
- 只有当元素没有条件，或其条件所需的上下文值均存在时，才会校验元素
  - 这意味着，在多个上下文中使用的战利品元素可以通过带条件的元素来避免校验错误
  - 带条件的元素包括：
    - `minecraft:number_dispatcher` 各个分支中的 `condition` 字段，适用于 `minecraft:context_float_provider` 和 `minecraft:context_int_provider` 两种类型
    - `minecraft:villager_trade` 中的 `merchant_predicate` 条件字段
    - 战利品池、战利品池条目和战利品函数中的 `condition` 字段
- 校验错误现在会阻止命令编译，既适用于函数中的命令，也适用于控制台输入的命令
  - 例如，`compute entity @s float {type: "minecraft:enchantment_level",amount:{type:"minecraft:linear",base:0.15,per_level_above_first:0.15}}` 现在会编译失败，因为它在 `minecraft:command_compute_entity` 上下文中使用了 `minecraft:enchantment_level`，而此上下文不提供所需的信息（`minecraft:enchantment_level`）
- 将 `minecraft:command` 上下文拆分为 `minecraft:command_predicate` 和 `minecraft:command_modifier`
  - 前者用于命令中的谓词，例如 `/execute if predicate`
  - 后者用于物品修饰器，例如 `/item ... modify` 函数中的物品修饰器
- 为方便了解校验规则，加入了新的报告：`loot_context_requirements.json`
  - 某个上下文中列为 `allowed` 的值，可供在此上下文中运行的待校验元素使用
  - 命令参数所使用的上下文可在 `commands.json` 报告中以下参数类型的 `context` 字段中找到：
    - `minecraft:context_float_provider`
    - `minecraft:context_int_provider`
    - `minecraft:loot_modifier`
    - `minecraft:loot_predicate`
    - `minecraft:loot_table`
    - `minecraft:slot_source`

### 命令

- 更改了命令报告格式：
  - 参数信息现在位于 `argument` 字段中，而非合并到父节点中
  - 现在提供命令建议信息

#### 加入了 `pattern` 参数

- 加入了用于匹配正则表达式模式的命令参数类型
- 加入此参数是为了更好地支持服务端模组和插件添加的命令

### 标签

#### 方块标签

- 加入了 `#triggers_ambient_ice_block_sounds`，包含所有会触发冰播放环境音效的方块
- 加入了 `#triggers_ambient_ice_crystal_sounds`，包含所有会触发冰晶播放环境音效的方块

## 资源包版本 103.0

### UI 精灵图

- 加入了新的 UI 纹理：
  - `friends/tab_focused.png`

### 音效

- 加入了新的声音事件：
  - `entity.frostbite.throw`

### 着色器与后处理效果

- 重构了 `terrain.vsh`，以解码新的顶点数据打包格式

#### 顺序无关透明着色器

- 将 OIT 着色器改为依赖子通道
  - 更改了 `core/oit_composite.fsh`、`core/oit_depth_bounds_cull.fsh`、`include/oit_depth_sample.glsl`、`include/oit_sample.glsl`
  - 加入了 `core/blit_depth_bounds.fsh` 着色器，用于在子通道上下文中复制深度边界

#### 船的水体遮罩着色器

- 更改了水体遮罩的处理方式，以支持 OIT 中的子通道
  - 它现在渲染到一个独立目标中，并在渲染地形时采样该目标，而非渲染到地形深度缓冲区
  - 更改了 `core/rendertype_water_mask.fsh` 和 `core/terrain.fsh`
  - 移除了 `core/blit_depth.fsh`
  - 无论是否启用 OIT，都会使用此方案
