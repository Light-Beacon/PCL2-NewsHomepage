## 新特性

- 加入了斑驳森林生物群系。
- 加入了杨树。
- 加入了倒下的杨树。
- 加入了红色杨树树叶、橙色杨树树叶和黄色杨树树叶方块。
- 加入了杨木系列方块。
- 加入了层孔菇。
- 加入了红灌木。
- 加入了废弃营地结构。
- 加入了新的探险家地图。
- 加入了坐垫。
- 加入了麦秆床。
- 为所有羊毛方块加入了羊毛楼梯和羊毛台阶。
- 为所有混凝土方块加入了混凝土楼梯和混凝土台阶。
- 旁观模式的玩家现在可以与传送门交互以传送。
- 改进了Realms，包括创建和管理邀请码的功能。
- 加入了哥特语支持。

### 斑驳森林生物群系

- 一种新的森林生物群系，可以在寒冷生物群系附近找到。
- 会生成杨树和倒下的杨树。
- 可以在杨树和倒下的杨树上找到层孔菇。
- 会生成红灌木。
- 以下被动生物和中立生物会在斑驳森林中生成；具有寒冷变种的生物会使用寒冷变种：
  - 绵羊
  - 鸡
  - 牛
  - 猪
  - 兔子
  - 狐狸
- 可以找到新结构废弃营地的斑驳森林变种。

### 杨树

- 一种新的树木，有三种颜色变种：
  - 红色杨树树叶
  - 橙色杨树树叶
  - 黄色杨树树叶
- 每种变种都有与其树叶颜色对应的飘落树叶粒子。
- 杨树树叶会掉落杨树树苗，树苗会随机长成三种变种之一。
- 杨树树苗可以通过与流浪商人交易获得。
- 杨树上或周围会自然生成层孔菇和枯叶堆。
- 树干由杨木原木构成。
- 杨木原木可以制作成新的杨木系列方块。

### 层孔菇

- 一种新的蘑菇，会生成在杨树和倒下的杨树上。
- 有小型和大型两种尺寸。
- 对小型层孔菇使用骨粉可以使其长成大型层孔菇。
- 大型层孔菇被破坏后会掉落两个层孔菇物品。
- 可以像其他蘑菇一样用于制作煲类食物。
- 可以通过与流浪商人交易获得。
- 踩在层孔菇上时会产生轻微的弹跳效果，类似于床。
- 活体实体在层孔菇上弹跳时，层孔菇会发出弹跳音效。

### 红灌木

- 一种新的装饰性植物方块，可以在斑驳森林中找到小片分布的红灌木。
- 可用于堆肥桶。
- 对红灌木使用骨粉时，如果条件允许，会在随机的相邻位置长出一株红灌木。

### 坐垫

- 坐垫是一种玩家可以放置在世界中，并通过交互坐上去的物品。
- 可以制作16种颜色变种。
- 使用3个相同颜色的羊毛台阶合成。

#### 坐垫放置规则

- 坐垫可以放置在任意平坦表面上。
- 坐垫在水平方向上始终与方块网格对齐，在垂直方向上则位于支撑表面的顶部。
- 坐垫不能被活塞移动。
- 支撑方块被移除后，坐垫会被破坏。
- 坐垫没有碰撞体积，可以与其他物体重叠，但不能与其他坐垫重叠。

### 麦秆床

- 麦秆床是一种新型的床，可以通过睡觉跳过夜晚，而不会设置重生点。
- 只能使用一次，使用后会被摧毁。
- 不能在下界或末地使用；如果尝试在那里睡觉，麦秆床会被摧毁。
- 使用3个干草捆可以合成4个麦秆床。
- 统计信息窗口中加入了玩家在麦秆床上睡觉次数的新统计信息。

### 顺序无关透明（OIT）

- 通常，半透明表面需要按从后向前的顺序渲染，才能避免视觉问题。
  - 为此，需要在渲染前对半透明几何图形进行排序。
  - 这一过程开销很大；即便每个三角形都得到完美排序，相交的三角形仍无法被正确渲染。
- 在本次更新之前，“改进透明显示”视频设置会尝试缓解与半透明有关的视觉问题。
  - 它会将不同类型的半透明物体（实体、粒子、水等）渲染到不同纹理，再将这些纹理合成为最终图像。
  - 这让我们能够以一定的性能代价修复部分问题。
  - 但也引入了一些不太明显的其他问题。
- 现在，“改进透明显示”视频设置会启用一种新的顺序无关透明算法，以下简称OIT。
  - 无需排序，就能以任意顺序渲染半透明物体。
  - 修复了现有的所有主要半透明视觉问题，例如透过半透明物体观察时某些物体消失的问题。
  - 不过，该算法是一种近似算法，因此也会引入一些新的轻微视觉瑕疵，例如透过多层半透明表面观察时，云的颜色会略有偏差。
- 我们预计OIT的性能开销会高于此前“改进透明显示”的实现方式。
- 关闭“改进透明显示”时，渲染行为基本不变；游戏仍会在必要时对几何图形排序，并优先考虑性能。

> **开发者注：** 特别感谢Rubén Osorio López、Jozufozu以及整个Minecraft模组社区分享相关信息，帮助我们实现这一功能。

### 方块、物品和实体的细微调整

- 末影人在骑乘其他实体时，现在会受到弹射物伤害。
- 食用紫颂果后随机传送时，现在会显示指向传送方向的粒子。
- 末影人和潜影贝不再会传送到基岩上。
- 犰狳浸没在液体中时，不再尝试蜷缩。
- 拥有管理员权限的玩家对刷怪笼使用刷怪蛋时，刷怪蛋上设置的数据现在会传递给刷怪笼。
- 破坏饰纹陶罐掉落的陶片现在会保留数据，例如自定义名称。
- 物品因保护亡灵生物免受阳光伤害而损耗耐久度时，魔咒现在也会生效。
- 使用末影珍珠传送时，现在会重置被传送玩家的动量。

### 用户界面

- 移除了“原始输入”鼠标设置。
  - 在世界中游玩时，鼠标输入现在始终使用相对鼠标模式。
- 按键绑定现在使用物理按键，而非特定键盘布局的键码。
- 无边框全屏现在是默认全屏模式。
- 在无边框全屏和独占全屏间切换不再需要重启游戏。
- 启用独占全屏时，光标现在会被限制在窗口内。
- 最小窗口尺寸现在为320×240像素。
- 在macOS上，输入文本时按住某个按键，现在会显示系统原生的重音字符和候选弹出菜单。
- 在Linux上，如果Wayland可用，游戏现在会优先使用原生Wayland。
- 修复了Realm所有者无法将自动区域偏好设为Realm区域的问题。
- 在控制设置中加入了“退出游戏快捷键”选项，控制能否使用键盘快捷键关闭游戏（Windows/Linux上的Alt + F4，以及macOS上的Cmd + Q和Cmd + W）。
  - 默认开启。
- 在macOS的控制设置中加入了“右键单击模拟”选项，将Control + 左键视为右键。
  - 默认关闭。
- 在macOS的视频设置中加入了“菜单/程序坞可见性”选项，控制全屏时能否通过将鼠标移至屏幕边缘来显示macOS菜单栏和程序坞。
- 为Realms加入了对加拿大、墨西哥、南非及美国亚利桑那州额外服务器区域的支持，以便未来这些区域可用时使用。

#### 调试叠加层

- 调试叠加层现在支持使用独立于游戏其他界面的界面尺寸。
  - 可以通过`F3 + F6`打开的调试选项界面自定义。
  - 默认尺寸为“自动”，会尝试保持比普通界面更高的分辨率。
  - 另一个选项为“不变”，会与常规界面尺寸一致。
  - 其余选项与普通“界面尺寸”相同，直接控制缩放尺寸。
- 加入了`player_speed`调试条目，以方块/游戏刻为单位显示玩家速度。
- 调试叠加层现在会显示显示器刷新率。

#### 世界选项

- “世界选项”按钮移到了原先“对局域网开放”的位置，可从暂停菜单打开。
  - 世界选项界面分为“常规”和“多人游戏”两部分。
    - “常规”部分包含以下选项：
      - 默认游戏模式：世界的默认游戏模式，等同于`/defaultgamemode`命令。
      - 个人游戏模式：你在当前世界中正在使用的游戏模式，等同于`/gamemode`命令或F3 + F4。
      - 允许命令：控制你能否在此世界中使用命令。
      - 难度：控制世界难度，等同于`/difficulty`命令。
      - 编辑游戏规则：打开游戏规则界面，查看和编辑世界的游戏规则。
      - 限制：查看你在此世界中的限制。
    - “多人游戏”部分包含以下选项：
      - 局域网：更改世界的多人游戏开放范围。
      - 端口：对局域网开放世界时使用的端口号。
      - 命令权限：控制加入此世界的玩家能否使用命令。
      - 强制游戏模式：控制是否强制其他玩家的游戏模式与世界默认游戏模式一致。
- 用于打开在线选项界面的“在线”按钮，现在会始终显示在选项菜单中。

### 命令

#### 加入了`posteffect`

- 允许为玩家添加或移除“后处理效果”。
- 这些是游戏完成常规渲染后，应用于玩家画面的后处理着色器。
- 后处理效果存在于客户端的资源包中，而非服务端；服务端无法得知效果是否实际生效。
- 后处理效果此前已是资源包格式的一部分，但只有少数硬编码效果可用。

> **开发者注：** 现在可以充分使用资源包中的自定义着色器了。不过请注意，着色器仍可能随时更改，相关功能（命令、后处理效果或着色器）未来也可能重新设计。

语法：

- `/posteffect add <player> <posteffect>`：如果玩家尚无该后处理效果，则添加它。
- `/posteffect clear <player>`：移除玩家的所有后处理效果（如果有）。
- `/posteffect list <target>`：列出应用于玩家的所有后处理效果（如果有）。
- `/posteffect remove <player> <posteffect>`：如果玩家具有该后处理效果，则移除它。

#### 对`publish`的更改

- 移除了`gamemode`参数。
  - 应改用`defaultgamemode`命令或世界选项界面中的游戏模式按钮设置世界的默认游戏模式；针对特定玩家的游戏模式则使用`gamemode`命令设置。

#### 加入了`compute`

- 在各种上下文中对`minecraft:context_int_provider`和`minecraft:context_float_provider`求值。
- 所有上下文中的`origin`均设为当前命令上下文的位置，`this`实体设为`@s`。
- 如果求值失败（例如除以零），命令会失败。

语法：

- `/compute <target> integer <int_provider>`，或
- `/compute <target> float <float_provider> [<scale>]`，其中：
  - `<target>`：以下选项之一：
    - `default`：在`minecraft:command_compute_default`上下文中运行提供器，只有通用参数（位置和`this`实体）可用。
    - `block <pos>`：在`minecraft:command_compute_position`上下文中运行提供器，根据`<pos>`处的方块设置方块状态和方块位置。
    - `entity <entity selector>`：在`minecraft:command_compute_entity`上下文中运行提供器，`target_entity`设为选择器的结果。
  - `<int_provider>`：`minecraft:context_int_provider`注册表中的元素，或内联值。
  - `<float_provider>`：`minecraft:context_float_provider`注册表中的元素，或内联值。
  - `<scale>`：可选的缩放值，默认为`1.0`。
    - 最终结果会乘以`<scale>`，再向负无穷方向取整。

#### 对`data`的更改

- 为`/data modify ... append|insert|merge|prepend|set`加入了名为`compute`的新来源。
- 对`minecraft:context_int_provider`或`minecraft:context_float_provider`求值，然后以整数或浮点数标签形式提供结果。
- 示例：`/data modify storage foo bar set compute entity @n[type=minecraft:armor_stand] integer {type:score,target:{type:context,target:target_entity},score:baz}`

语法：

- `compute <target> (integer <int_provider> | float <float_provider>)`，其中`target`、`int_provider`和`float_provider`的语法与`/compute`相同。
  - 注意：与`/compute`不同，这里没有`scale`，因为浮点数结果会直接存储，而非以整数形式作为命令结果返回。

#### 对`give`的更改

#### 对`item`的更改

- 此前使用槽位参数的位置，现在改为接受槽位来源。
  - 使用`minecraft:command_slot_source`战利品类型求值。
  - 可以使用内联或引用形式的槽位来源。
  - 可以使用指向多个槽位的槽位来源。
  - `replace`子命令具有新的语义：
    - 按槽位来源提供的顺序，使用相应的来源物品逐一替换每个目标槽位的内容。
    - 目标槽位多于来源物品时，忽略剩余槽位。
      - 示例：`replace [12345] with (ABC)` → `[ABC45]`
    - 目标槽位少于来源物品时，忽略剩余物品。
      - 示例：`replace [123] with (ABCDE)` → `[ABC]`
  - 仍允许使用`<slot_type>`或`<slot_type>.<slot_number>`形式的字符串槽位范围。
    - 可以是单个槽位，例如`armor.chest`。
    - 也可以是多个槽位，例如`container.*`。
    - 作为使用该槽位范围的`minecraft:slot_range`槽位来源的简写。
      - 示例：`hotbar.4`等同于`{type:"minecraft:slot_range",slots:"hotbar.4"}`。
- `from entity`物品来源中的实体参数现在可以是指向多个实体的选择器。
  - 指向多个实体时，会将各实体提供的槽位依次拼接。
- 加入了`fill`和`override`子命令，语法均与`/item replace`相同。
  - `/item fill`
    - 使用来源物品填充每个目标槽位。
    - 目标槽位多于来源物品时，会重复使用这些物品，直至填满所有槽位。
      - 示例：`fill [12345] with (ABC)` → `[ABCAB]`
  - `/item override`
    - 使用对应的来源物品覆盖每个目标槽位的内容。
    - 目标槽位多于来源物品时，会清空剩余槽位。
      - 示例：`override [12345] with (ABC)` → `[ABC__]`（`_`表示空槽位）。

#### 对`execute`的更改

- 加入了`slots`条件子命令。
  - 统计槽位来源中实际存在于目标方块或实体上的槽位数量。
  - 槽位来源使用`minecraft:command_slot_source`战利品类型求值。
  - 语法：
    - `/execute if|unless slots block <pos> <slot source>`
    - `/execute if|unless slots entity <targets> <slot source>`
- `items`条件子命令现在接受槽位来源参数，替代槽位参数。
  - 槽位来源使用`minecraft:command_slot_source`战利品类型求值。
  - 语法：
    - `/execute if|unless items block <pos> <slot source> <item predicate>`
    - `/execute if|unless items entity <targets> <slot source> <item predicate>`

#### 对`place`的更改

- `feature`子命令现在允许内联定义地物。

#### 对`spreadplayers`的更改

- 方块是否可作为安全的玩家分散位置，现在由`#entities_can_teleport_to`方块标签控制。

#### 对`swing`的更改

- 对玩家使用时，不再重置玩家的攻击强度。
- 加入了可选参数，用于设置播放的挥动动画。
  - 允许值：`none`、`whack`、`stab`。
  - 省略时默认为`whack`。
- 加入了设置所提供挥动动画持续时间的新参数。
  - 格式：正数时间值，默认单位为游戏刻。
  - 省略时默认为`6t`。

    - `size`：要求状态效果列表具有指定长度，也可使用`min`和`max`匹配长度范围。

`mob_effects`谓词的格式是从效果类型到其属性的映射。所有字段均可选，只有提供的字段参与匹配。

```text
{
  "minecraft:<效果类型>": {
    "duration": <以游戏刻为单位的持续时间整数范围>,
    "amplifier": <整数范围>,
    "ambient": true/false,
    "visible": true/false
  }

```

以下示例匹配多个不同的效果和条件：

```json
"effects": {
  "minecraft:jump_boost": {
    "duration": 3600,

      "max": 3600

      "min": 2
```

所有条件均可选。

### 配方

#### 药水酿造配方

药水酿造配方现在由数据驱动。可以通过数据包添加新配方，也可以修改原版配方。酿造配方使用`minecraft:brewing`类型。

主要内容如下：

- `input`：药水原料，具有必需的`item`字段，以及可选的`potion_contents`字段；后者使用`minecraft:potion_contents`数据组件谓词。
- `reagent`：酿造材料，具有必需的`item`字段，以及可选的`potion_contents`字段；后者使用`minecraft:potion_contents`数据组件谓词。
- `output`：物品堆叠；产出的物品。

以下是一个原版配方示例：

```json
{
  "type": "minecraft:brewing",
  "input": {
    "item": "minecraft:potion",
    "potion_contents": {
      "potion": "minecraft:water"
    }
  },
  "output": {
    "components": {
      "minecraft:potion_contents": {
        "potion": "minecraft:awkward"
      }
    },
    "id": "minecraft:potion"
  },
  "reagent": {
    "item": "minecraft:nether_wart"
  }
}
```

三个槽位都可以使用任意物品，例如：

```json
{
  "type": "minecraft:brewing",
  "input": { "item": "minecraft:bucket" },
  "output": { "id": "minecraft:sulfur_cube_bucket" },
  "reagent": { "item": "minecraft:potent_sulfur" }
}
```

**生成目标**

更新了`spawn_target`字段，允许使用任意密度函数，而不再仅限于`noise_router`字段中定义的部分函数。

候选出生位置的适宜程度，通过在某个任意维数的空间中，计算其到一组目标超立方体的欧几里得距离平方来确定。

例如，一个轴可以是`temperature`，另一个轴是`erosion`，适宜程度由到`temperature=0.1，erosion=0.2`与`temperature=0.3，erosion=0.5`之间矩形区域的距离决定。这会同等优先选择位于这些范围内的候选出生点，同时降低远离该范围的候选点的优先程度。

格式：目标超立方体列表。

- 目标格式：从密度函数ID到该轴范围的映射。
  - 范围可用以下形式指定：
    - 浮点数：精确的目标值。
    - 两个浮点数的数组：`[min, max]`形式的目标范围。
    - 包含以下字段的对象：
      - `min`：浮点数；目标范围最小值。
      - `max`：浮点数；目标范围最大值。

#### 材料规则

**材料规则注册表**

加入了新的数据驱动注册表，从`data/<namespace>/worldgen/material_rule/<id>.json`加载。

此注册表的元素定义一条处理流程，用于选择世界中给定位置应放置的基础方块。

格式与此前噪声设置文件中`surface_rule`字段的格式相同，并具有以下扩展：

#### 噪声

更新了噪声的格式，适用于`worldgen/noise`注册表中的噪声，以及基于噪声的方块状态提供器中内联定义的噪声。

噪声定义分形布朗运动（fBm）配置，具有以下属性：

- 输出值近似服从正态分布。
- 除非另有指定，输出振幅适配至`[-1; 1]`。
  - 由于正态分布的性质，实际意味着99.7%的样本落在此范围内，但仍可能出现范围外的值。
- 参数为持续度0.5、间隙度2.0。
  - 即相邻倍频层之间，振幅减半，频率加倍。
- 种子处理稳定，可以增强、静音或添加某个倍频层，而不影响其余倍频层。
- 将`firstOctave`重命名为`base_octave`。
- 加入了`base_amplitude`：正浮点数；应用于噪声输出的缩放因子。
  - 缺省时为`1.0`。
- 加入了`octave_count`：1至32之间的整数；采样的倍频层数量。
- 加入了`normalize`：布尔值或`"legacy"`；控制如何归一化输出振幅。
  - 为`true`时，`base_amplitude`是输出的预期振幅，即99.7%的样本在`[-base_amplitude; base_amplitude]`内。
  - 为`false`时，`base_amplitude`是第一个倍频层的振幅。
  - 为`"legacy"`时，沿用旧格式的归一化行为。
    - 这通常会得到比预期更小的范围。
  - 缺省时为`true`。
  - 注意：归一化*不受*`amplitude_modifiers`字段影响，因此修改单个倍频层的振幅不会影响其他倍频层的振幅。
- 将`amplitudes`重命名为`amplitude_modifiers`：浮点数列表；应用于各倍频层的缩放因子。
  - 列表元素数量必须与`octave_count`一致。
  - 如上所述，该缩放因子绕过归一化，会影响输出振幅。
  - 此字段不再必需，缺省时全部为`1.0`。

#### 密度函数

- 密度函数和噪声不再使用双精度浮点数求值，而改用单精度。

### 装备资源

新的可选字段`trim_overrides`可用于为指定装备资源替换特定纹饰材料或图案所使用的纹理或调色板。它替代了此前纹饰材料中的`override_armor_assets`以及自定义图集覆盖所支持的功能。

- 格式：覆盖条目列表，包含以下字段：

  - `texture`：可选纹饰图案资源ID；此条目匹配时使用的替换纹理。
    - 纹理的指定格式与`asset_id`相同。
    - 缺省时使用该图案的默认纹理。
  - `palette`：可选调色板ID；此条目匹配时使用的替换调色板。
    - 缺省时不对纹理进行调色板重映射。
  - 始终选择第一个匹配的条目。
  - 必须至少定义`texture`或`palette`之一。

- 与其他资源包资源一样，如果多个资源包都定义了此效果，则应用列表中最后一个资源包的定义。
