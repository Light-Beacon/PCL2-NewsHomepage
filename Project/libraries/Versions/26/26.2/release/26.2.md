探索这个布满沸腾硫黄池、令人惊艳的洞穴生物群系，用硫黄和朱砂建造，并见识硫方怪对方块那奇特的好胃口！从弹跳、滑行到爆炸惊喜，这种难以捉摸的生物为建造、竞速和生存带来了全新的玩法。现在就到 Minecraft 里体验混沌立方吧！

### 硫方怪

- 加入了硫方怪生物
- 会在新的硫黄洞穴生物群系中生成
- 当玩家手持方块与其交互时：
  - 硫方怪会吸收该方块
  - 其 AI 会被禁用
  - 体内有方块时：
    - 硫方怪会变成一个可被推动的实体物体：
      - 不会受到摔落伤害或来自玩家的伤害
      - 玩家可以击打和推动它
    - 它会获得下列原型之一，并据所吸收的方块改变自身的物理属性
    - 玩家可以使用剪刀与其交互：
      - 这会移除其体内吸收的方块
      - 硫方怪的 AI 会重新启用
- 硫方怪会跟随手持其可吸收方块的玩家
- 硫方怪会寻找附近的方块掉落实体，并移动过去将其吸收
- 被击杀时，硫方怪会分裂成两个更小的硫方怪
- 可以用黏液球喂食小型硫方怪，使其长成大型硫方怪
- 可以用空铁桶捡起大型硫方怪
- 硫方怪无法进入船，但可以乘坐矿车
- 发射器可以：
  - 为硫方怪放入或更换体内的方块
  - 使用剪刀移除其体内的方块
  - 用硫方怪桶生成一个硫方怪
- 河豚不会被硫方怪吓到

#### 硫方怪原型

- 每种原型的特征在于：硫方怪被击中后的速度、与方块和可碰撞实体碰撞时的弹性、地面摩擦力、空气阻力，以及是否会在液体中漂浮
- 目前有下列原型：
  - 普通：中等速度、中等弹性、中等地面摩擦力以及较低的空气阻力
    - 具有浮力
    - 用于吸收松散矿物和泥土类方块时
  - 弹性：高速度、高弹性、中等地面摩擦力以及较低的空气阻力
    - 具有浮力
    - 用于吸收木质方块时
  - 缓慢弹性：低速度、高弹性、中等摩擦力以及中等空气阻力
    - 用于吸收石头类方块时
  - 缓慢平移：低速度、低弹性、中等地面摩擦力以及中等空气阻力
    - 用于吸收金属方块时
  - 快速平移：高速度、低弹性、中等地面摩擦力以及较低的空气阻力
    - 用于吸收有机方块时
  - 轻盈：低速度、高弹性、中等地面摩擦力以及较高的空气阻力
    - 具有浮力
    - 用于吸收羊毛方块时
  - 快速滑行：高速度、无弹性、较低的地面摩擦力以及较低的空气阻力
    - 用于吸收冰类方块时
  - 缓慢滑行：低速度、无弹性、较低的地面摩擦力以及较低的空气阻力
    - 用于吸收蘑菇类方块时
- 此外还有下列特殊原型：
  - 高阻力：速度极慢、阻力与弹性较低，但地面摩擦力极高
    - 用于吸收灵魂沙和灵魂土时
  - 黏性：属性与快速平移原型相同，但以极高的地面摩擦力和无弹性来模拟黏性
    - 用于吸收蜜脾块时
  - 爆炸：与普通原型的属性类似，但空气阻力略高
    - 用于吸收 TNT 时
    - 吸收的 TNT 可以被红石、火源（包括装有打火石的发射器）或附近的爆炸激活
    - 被火或红石激活时，吸收的 TNT 引燃时间为 6 秒
    - 被爆炸激活时，吸收的 TNT 引燃时间在 0.75 至 3 秒之间随机
    - 体内有已激活 TNT 的硫方怪无法用铁桶装起
    - 已激活的 TNT 无法用剪刀剪出
    - 爆炸后不会生成小型硫方怪
  - 高温：与普通原型的属性相同，但会伤害接触到的实体
    - 用于吸收岩浆块时

### 烈性硫黄

- 是会在硫黄洞穴生物群系内的水池中自然生成的新方块
- 会产生气泡，向上穿过最多 4 格水源方块
- 放置在不超过 4 格水源方块下方时，会在水面生成一团令人反胃的气体
  - 这团气体会沿相邻的水面扩散，最大半径为 3 格
- 可以用 9 个硫黄合成
- 放置在岩浆块或熔岩上方、且处于 1-4 格水源方块下方时，会形成间歇泉
- 下方是岩浆块时，间歇泉会随机间隔喷发，向上喷出水粒子，并对上方的实体施加向上的冲量
- 下方是熔岩时，间歇泉会连续喷发，但声音比下方是岩浆块时略弱
- 间歇泉在开始和结束喷发时会发出可被幽匿感测体检测到的游戏事件

### 硫黄尖锥

- 是会在硫黄洞穴生物群系内的硫黄上自然生成的新方块
- 放置在天花板时为钟乳石形态，放置在地面时为石笋形态
- 可以拼接成更长的钟乳石与石笋
- 尖端相邻时钟乳石与石笋会连接，但潜行放置时不会
- 钟乳石形态的硫黄尖锥放置在硫黄下方时可以生长
- 石笋形态下方没有依附物时会被破坏
- 钟乳石形态上方没有依附物时会掉落
- 被掉落的钟乳石砸中会受伤，因为它很尖！
- 石笋形态不尖，落在上面不会受到额外伤害
- 投掷的三叉戟可以破坏硫黄尖锥
- 4 个硫黄尖锥可以合成 1 个硫黄

### Vulkan 支持

- 正如此前宣布的，我们打算将游戏从 OpenGL 切换到 Vulkan
- 较老的硬件或驱动不支持 Vulkan，在这些情况下会回退为使用 OpenGL
  - 目前的要求是支持动态渲染和推送描述符的 Vulkan 1.2，但此要求今后可能提高或降低
- 目前这仍是实验性的渲染后端，性能和稳定性可能较差
  - 请将其相关漏洞反馈到我们的漏洞追踪器
- 在 Vulkan 下，我们会优先使用**独立显卡**而非集成显卡，这与 OpenGL 不同
- 可以在 `F3` 调试叠加层（`system_specs` 部分）查看当前使用的后端
- 在 macOS 上，我们使用 MoltenVK 将 Vulkan 转译为 Metal

### "图形API"视频设置

- 这是"视频设置"中新增的选项
- 有三个值：**默认**、**优先使用Vulkan（实验性）**和**优先使用OpenGL**
- "默认"可能会由我们酌情更改，我们推荐所有用户使用此项，除非遇到问题需要更改
  - 目前它与"优先使用OpenGL"相同
- "优先使用Vulkan（实验性）"会尝试使用 Vulkan 渲染，若不可用则回退为 OpenGL
  - Vulkan 支持目前是实验性的，在某些系统上使用它可能会降低性能或导致不稳定
- "优先使用OpenGL"会尝试使用 OpenGL 渲染，若不可用则回退为 Vulkan

#### 启动与回退行为

- 若在设置为"优先使用Vulkan（实验性）"时游戏在启动时崩溃，该设置会自动改为"默认"
- 设置为"默认"时，游戏仍会在启动时尝试收集与 Vulkan 有关的系统信息
- 若在设置为"默认"时游戏在启动时崩溃，该设置会自动改为"优先使用OpenGL"
  - 设置为"优先使用OpenGL"时，游戏不会与 Vulkan 产生任何交互，以免因此导致崩溃

## 技术性更改

- 数据包版本号现为 `107.1`
- 资源包版本号现为 `88.0`
- 使用 Tracy 分析游戏性能（以 `--tracy` 启动）时，现在也会包含 GPU 耗时
- 现在渲染使用反向深度缓冲，这有助于在大部分硬件上改善深度冲突
- 调试屏幕的 `fps` 选项现在会报告所使用的呈现模式类型（例如 `mailbox` 或 `fifo relaxed`），而不再仅显示 `vsync`
- `particle_render_stats` 现在包括不同粒子组的数量（`SQ` 表示 `single quads`、`NR` 表示 `no render`、`EG` 表示 `elder guardians`、`IP` 表示 `item pickup`），以及粒子总数量
- 如果玩家没有对应记分项，玩家标签叠加层上不再显示玩家的分数
- 更新了遥测

### 服务器属性

- 加入了 `chat-spam-threshold-seconds` 和 `command-spam-threshold-seconds` 属性，将聊天与命令的滥发阈值分开
  - 两个阈值默认均为 10，这也是先前命令与聊天合并在一起的阈值
  - 这些阈值用于配置因聊天消息或命令发送过多而自动踢出玩家的机制
  - 该值描述的是玩家必须持续滥发多少秒才会被踢出，玩家每发送一条消息，计数器增加 1 秒
  - 计数器每游戏刻减少一次（相当于 1/20 秒），计数器达到所配置的阈值时玩家会被踢出
  - 任一阈值设为 0 即可禁用对应类型滥发消息的踢出
  - 在默认阈值 10 下，以下消息频率会导致踢出：
    - 1 秒内发送 11 条消息
    - 2 秒内发送 14 条消息
    - 10 秒内发送 21 条消息

### 遥测

#### 世界事件中的新属性

- `server_session_id`：多人游戏会话的唯一标识符，同一会话中的所有玩家共享该值
  - "会话"定义为至少有一名玩家在服务器中的连续时间段
  - 此属性为必要属性，不受选择加入设置影响

#### 新的必要事件

- `graphics_capabilities`
  - 这是会在启动时发送的新事件，用于告知我们用于运行游戏的图形设备的功能
  - 加入了新属性 `backend_name`
    - 其值为 `Vulkan` 或 `OpenGL`，用于帮助我们了解玩家使用的图形 API
  - 加入了新属性 `backend_failure_reason`
    - 其值为一组简短的错误代码，例如 `vulkan_device_version_too_low`，用于帮助我们识别目标 Vulkan 要求方面的问题
  - 加入了新属性 `backend_failure_message`
    - 其值为简短而笼统的信息，例如 `Failed to find the GLFW platform surface extensions`，用于在玩家运行 Vulkan 遇到问题时帮助我们缩小范围
  - 加入了新属性 `backend_failure_missing_capabilities`

#### 实体谓词

实体谓词格式已从包含多个可选字段的结构更改为类似于数据组件映射的结构。

例如，`effects` 此前是一个可选字段：

```text
{
    "effects": {...}
}
```

在此版本中，它变成了组件式的子谓词条目：

```text
{
    "minecraft:effects": {...}
}
```

主要功能更改如下：

- 实体谓词中所有的键现在均为命名空间 ID
  - 由于命名空间 ID 可以省略命名空间（默认为 `minecraft` 命名空间），现有的字段名依旧有效
  - 例外：字段 `type` 已重命名为 `minecraft:entity_type`
- 现在未知的子谓词组件会被拒绝（此前未知字段会被忽略）

现有的特定类型子谓词已重命名并移至顶层。

- `minecraft:lightning` → `minecraft:type_specific/lightning`
- `minecraft:fishing_hook` → `minecraft:type_specific/fishing_hook`
- `minecraft:player` → `minecraft:type_specific/player`
- `minecraft:raider` → `minecraft:type_specific/raider`
- `minecraft:sheep` → `minecraft:type_specific/sheep`
- `minecraft:slime` → `minecraft:type_specific/cube_mob`，因为现在除史莱姆和岩浆怪外，它也包括硫方怪

例如：

```json
{
  "type_specific": {
    "type": "minecraft:player",
    "looking_at": {
      "type": "minecraft:ender_dragon"
    }
  }
}
```

变为

```json
{
  "minecraft:type_specific/player": {
    "looking_at": {
      "minecraft:type": "minecraft:ender_dragon"
    }
  }
}
```
